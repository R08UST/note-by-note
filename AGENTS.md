# AGENTS.md

This file provides guidance to AI coding agents working with code in this repository.

Note by Note is a browser piano practice stand for a beginner with a MIDI keyboard (React 19 + Vite + TypeScript, no backend). The UI copy is Chinese. See `README.md` for what each tab does.

## Commands

```bash
npm run dev          # http://127.0.0.1:4317 (strictPort, COOP/COEP headers)
npm test             # vitest run, happy-dom, every src/**/*.test.ts(x)
npx vitest run src/judge/judge.test.ts      # one file
npx vitest run -t "rewinds"                 # by test name
npm run lint         # oxlint
npm run build        # tsc -b && vite build (type check happens here)
npm run fetch-models # ~213 MB homr ONNX weights into public/models/homr/ (gitignored); needed for 识谱 and before build
npm run smoke-library  # re-parse every library score and rewrite public/pieces/manifest.json
```

The bundled sight/rhythm banks (`src/train/banks/*.json`) are generated by `npx vite-node src/train/build-bank.ts`. They are the fixed 题库. Don't regenerate them unless the level rules in `src/train/curriculum.ts` change.

`src/score/libraryExpression.test.ts` parses real library scores; vitest runs workers with an 8 GB heap for it.

## Architecture

The pipeline is: MusicXML → `ScoreNote[]` → a mode engine that judges `PlayedEvent`s → `RunSummary` → Dexie.

- **Score model.** `src/judge/types.ts` defines `ScoreNote` (time in quarter-note beats, MIDI pitch, middle C = 60, staff 1 = R hand, staff 2 = L) and `PlayedEvent` (time in ms on the score clock). Nearly every module speaks these two types.
- **Parsing.** `src/score/parseMusicXml.ts` turns MusicXML into `ParsedScore` (notes plus time signatures, tempos, dynamics, pedals). It is pure and kept apart from drawing. OSMD drawing lives in `src/ui/ScoreView.tsx`. `src/score/osmdHeads.ts` collects the drawn noteheads and `src/score/mapNotes.ts` matches judged notes to them. When you change the parser, keep that mapping working (`scripts/audit-marks.mjs` checks it across the library).
- **Input.** Web MIDI (`src/midi/webmidi.ts`, can attach all ports), the computer keyboard (`src/midi/keyboardMap.ts`), and the on-screen keyboard all emit the same `PlayedEvent` stream (`src/midi/bus.ts`).
- **Timing.** `src/transport/clock.ts` maps an event's own timestamp onto the Tone.js transport and removes the count-in, so beat 0 of the score is 0 ms. The user's latency offset is subtracted in the judge.
- **Modes.** `WaitMode` (`src/modes/waitMode.ts`) holds the cursor on each attack until it is played, and doesn't score timing. `RhythmMode` (`src/modes/rhythmMode.ts`) wraps the pure `Judge` (`src/judge/judge.ts`), which judges each note within a per-note window (`BEGINNER_TOLERANCE`, `MIN_WINDOW_MS`). `src/modes/marks.ts` adds `optional` strikes implied by ornaments and graces when "honour marks" is on. Matching an optional strike counts as a hit, and skipping one is never a miss.
- **Hooks drive the engines.** `src/ui/usePractice.ts` runs a 练习 session (hand selection, loops and spans, count-in, metronome, accompaniment, saving the run). `src/ui/useDrill.ts` is the lighter 训练 version. The run state transitions are pure in `src/ui/practiceMachine.ts`. `src/ui/PracticeApp.tsx` is the top-level shell: tabs from the URL hash (`src/ui/tabs.ts`), MIDI wiring, settings, and the library. `ScoreView`, `TrainTab`, and `OmrTab` are lazy-loaded.
- **Audio.** `src/audio/engine.ts` lazy-imports Tone.js and plays a velocity-layered sampled piano (`public/samples/`, built by `scripts/build-piano-layers.mjs`). `src/audio/performance.ts` compiles score marks (articulations, dynamics, ornaments, tremolos, tempo changes) into what the demo and accompaniment play. Judging ignores ornaments and tremolos.
- **Reports and storage.** `src/report/summary.ts` computes hit rate, offsets, spread, and errors per measure. `src/storage/db.ts` is the single Dexie database (settings, runs, user scores, train runs, bank marks, pitch stats).
- **Library.** `public/pieces/` holds about 1000 scores plus `manifest.json`, which `src/score/catalog.ts` reads (levels L1–L5, composer shelves). The manifest is generated by `scripts/smoke-library.mjs`, so don't hand-edit it. `src/score/pieces.ts` holds three built-in examples imported with `?raw`. The licenses of third-party scores go in `THIRD_PARTY.md`.
- **Training.** `src/train/` holds the curriculum (sight levels S1–S10 per hand, rhythm levels R1–R10), the generators, the fixed banks loaded through `import.meta.glob`, the item-serving rules (`bank.ts`: unseen first, no recent repeats, similarity limit), mastery, and the technique, ladder, and touch drills.
- **OMR.** `src/omr/` lazy-loads `homr-web` (AGPL) for photo/PDF → MusicXML in the browser. It prefers WebGPU and falls back to WASM, and it caches models in Cache Storage. Multi-page results are merged by `mergeMusicXml.ts`. OCR is on by default: `pageGeometry.ts` lays a PDF out at homr's 1920 px, and `textMarks.ts` writes the tempo and dynamic letters it reads into the first measure as printed directions.

## Conventions

- Most logic is pure and sits next to a `*.test.ts`. React components stay thin. Put new judging or timing logic in a pure module with a test, not in a hook.
- Comments and commit messages are plain full sentences that describe behaviour (for example, "Wait mode: a wrong note rewinds to the start of the measure."). User-facing strings are Chinese.
- `tsconfig.app.json` sets `verbatimModuleSyntax` and `erasableSyntaxOnly`. Use `import type` for types, and don't use enums, namespaces, or parameter properties.
- Production builds use `base: './'`, so asset paths must stay relative.
