# 01 导入流程与检查清单

> 往曲库里加谱子的完整步骤，以及 2026-11 几轮导入里踩过的坑。

## 一、总流程

```text
找候选 → 查许可 → 和曲库去重 → 下载 → 解析统计 → 符头对位审计 → 修或丢 → 写卡片 → smoke-library → 测试 → 提交 → 部署
```

### 1. 找候选

- **Vivace**：全目录在 `https://vivace-music.org/library/data/songs.json`，每首有 `instrument`、`source`、`license`、`difficulty`、`tags`、`sheetUrl`。只取 `instrument === "Piano"`。
- **PDMX**：下载 `https://zenodo.org/api/records/15571083/files/PDMX.csv/content`（225 MB）。过滤条件：
  - `tracks` 每一项都是 `0`（钢琴），且不超过两轨
  - `is_best_unique_arrangement === "True"`（同曲只取最佳编配）
  - 标题和副标题不含 easy / beginner / simplified / simple
  - 按 `n_views` 从高到低挑
- 谱子包 `mxl.tar.gz` 有 1.9 GB，只能整包下载。下载后用 `tar -xzf mxl.tar.gz -T 路径清单.txt` 只解压挑中的文件。上传者和 MuseScore 链接在 `metadata.tar.gz`（159 MB）里，字段是 `data.score.user.name` 和 `data.score.url`。

### 2. 查许可（每页都要看）

Vivace 页面上的来源说明在 `<p class="vsheet-source-credit">` 里。收和不收的规则：

| 来源说明 | 处理 |
|---|---|
| MuseScore 用户 + CC0 1.0 / Public Domain Mark 1.0（经 PDMX） | 收 |
| Chopin First Editions (NIFC) — CC BY 4.0 | 收，卡片必须写署名 |
| Mysterium: Scriabin corpus — CC BY 4.0 | 可收（本轮只挑了极少数） |
| KernScores / Humdrum — licence varies | **不收** |
| ASAP Dataset — CC BY-NC-SA 4.0 | **不收**（非商用） |
| Vivace 自己的简易改编，或不写许可 | **不收** |

作曲本身受版权保护的流行、动漫、游戏曲，按所有者的决定照样收，但卡片要写明，见 02。

### 3. 和曲库去重

按"作曲家姓 + 作品编号（Op./BWV/K./D./L./S./HWV/WoO/Hob.，带 No.）"比对；没有编号时按标题词重合 ≥ 60% 判断。机器判断以后**还要人工过一遍**，因为同一首曲子的标题写法差别很大，比如 "Träumerei" 和 "Dreaming (Träumerei), Op. 15 No. 7"。

### 4. 解析与结构检查

用 `scripts/audit-batch.mjs`（应用同款解析器）算音符数，再从 XML 读出小节数、调号、拍号、谱表数、声部数。直接丢掉的情况：

- **超过 400 小节**：一次练习装不下（如 Rhapsody in Blue、肖邦谐谑曲 Op. 31 / 39）
- **三行谱且中间一行是高音谱号**：左右手会分错（如《水之嬉戏》、柴可夫斯基《小序曲》）。三行谱是"高音 / 低音 / 低音"的可以收
- **两个声部各占两行谱**：会出现四行谱（如拉赫玛尼诺夫升c小调前奏曲）
- **解析出 0 个音**

### 5. 符头对位审计（`libraryMap.test.ts` 要求 100%）

每个判分音符都必须对应到 OSMD 画出来的一个符头。单独查一批：

```bash
node node_modules/rolldown/bin/cli.mjs scripts/audit-marks.mjs --format esm --platform node --file /tmp/audit.mjs
AUDIT_ROOT=<只放这批谱子的目录的上一级> node --expose-gc --max-old-space-size=8192 /tmp/audit.mjs
```

`AUDIT_ROOT` 下要有 `public/pieces/`。常见失败原因和处理办法：

| 报错 / 现象 | 原因 | 处理 |
|---|---|---|
| `Cannot set properties of null (setting 'font')` | happy-dom 没有 canvas，OSMD 量不了歌词、和弦标记的文字宽度 | 已在 `scripts/audit-marks.mjs` 里给 canvas 打桩，不用再改谱子 |
| `Invalid note initialization object: {}` | 13:8 之类的连音，VexFlow 换算不出时值。浏览器里同样画不出来 | 丢 |
| `谱上没有这一小节` 大量出现 | 两个声部小节数不一样（肖邦首版常见） | 丢 |
| `同一个位置的音已经标过了`、少量 `声部对不上` | 谱里有 `print-object="no"` 的隐藏音符，重复或补充了可见音 | 把隐藏的带音高音符改成等长隐藏休止符；和弦里的隐藏音直接删 |
| 少量 `时值对不上`、`本小节没有这个音高`，分散在多个小节 | 排版本身有错 | 丢（如舒伯特/李斯特《小夜曲》、莫扎特 K. 397） |

### 6. 写卡片

卡片字段：`id level title title_zh composer license attribution source_url file hands measures key time`。

- `id` 用书架前缀，例如 `pdmx-`。文件名与 id 相同，后缀 `.mxl`。
- `hands`：只有一行谱、只有一个声部时写 `one`，否则写 `two`。
- `level`：L1 单手旋律到 L5 演奏级。参照曲库里现有的曲子定，例如舒曼 Op. 68 No. 1 是 L3，肖邦叙事曲是 L5。
- 新作曲家要在 `src/score/composers.ts` 的中文名表里加一行，这样搜中文也能找到。

### 7. 生成清单与测试

```bash
npm run smoke-library     # 重新解析各书架，重写 manifest.json
npx vitest run src/score  # 含 libraryMap（符头 100%）和 libraryExpression（抽样检查力度、踏板等），约 15 分钟
```

每次跑完都要比对新旧 manifest 的 id：除了这次要删的，**不应该少任何一首**。

## 二、坑与经验

1. **内存**：audit-batch 在同一个进程里连续解析会累积内存。肖邦叙事曲有 6000 个音，一批 12 首就会爆。`smoke-library.mjs` 的 pdmx 书架因此改成每批 4 首；自己写的统计脚本也按每批 4 首处理。
2. **只写在 manifest 里的曲子会被删**：smoke-library 每次都用书架文件重建对应前缀。Luv Letter 原先只写在 manifest 里，每跑一次就会丢；现在已移进 `noctave.json`。新增曲子一定要写进书架文件。
3. **全库测试是抽样的**：`libraryExpression.test.ts` 每隔 N 个文件抽一首，曲库变大后会抽到以前没抽到的老谱子。2026-11-26 就这样抽出了踏板解析的 bug（已修，见 03）。
4. **`ls -l` 在 Windows 的 Git Bash 里列会错位**：用户名里有空格，看文件大小要用 `stat -c '%s'`。
5. **题库测试 `src/train/bank.test.ts` 在全量测试时偶尔超时**：单独跑能过。部署时如果只有它超时，可以先单独跑一次确认能过，再跳过测试部署。

## 三、下架一首曲子

1. 从对应书架文件（`noctave.json` / `pdmx.json` / …）里删掉条目，删掉 `public/pieces/` 下的谱子文件。
2. `npm run smoke-library`，比对 manifest，确认只少了这一首。
3. 如果那位作曲家已经没有别的曲子，删掉 `src/score/composers.ts` 里对应的中文名。
4. 在 `THIRD_PARTY.md` 记一笔，然后提交、部署。
